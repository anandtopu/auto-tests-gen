# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AI QE Platform PoC: an agentic test-engineering pipeline that (A) syncs E2E tests when a PR changes a source repo and (B) authors tests from a JIRA ticket, across a multi-repo estate. Orchestration is plain bash + Python; LLM phases run `claude -p` headlessly. `docs/architecture.md` (v2.7 — adds §5.19 the dominant defect class (C13), §5.18 spec-driven adoption, §5.17 observability, §5.5.1 the gate takes no orders from a run, §5.14 LLM Runner port, §5.15 attribution & routing integrity, §5.16 per-repo facts) is the authoritative design doc — section references like §5.8 in code comments point there. `implementation-plan.md` maps build phases B1–B5, and `REVIEW.md` records the multi-pass review and open items. User-facing docs: `docs/use-cases.md` (TASK-ORIENTED: 11 end-user use cases — PR sync, ticket coverage, plan review, onboarding, coverage gaps, flake quarantine, cost, provider switching, audit traceability, estate migration, run diagnosis — plus a "what this platform will not do" section; every command and exit code in it is verified against the source), `docs/getting-started.md` (demo walkthrough + troubleshooting), `docs/user-guide.md` (configuration reference, gate protocol, integration/onboarding), `docs/diagrams.md` (22 Mermaid diagrams — keep in sync when pipeline/gate behavior changes; #5 now shows the gate's config-trust boundary, #17 the LLM Runner port, #18 the attribution->routing chain), `docs/integrations/` (per-tool setup: OpenHands, Jira, Bitbucket Cloud + Stash/Server, Email/SMTP — `adapters/scm/stash.sh` is the Bitbucket Server/DC adapter, selected via `SCM_KIND=stash` — it resolves each repo's Stash project + slug PER REPO from the registry (`url: PROJECT/slug` or an explicit `stash_project:` field, via `engine/lib/stash_target.py`), so app repos and E2E repos can live under different projects; `STASH_PROJECT` is only the fallback default; `openhands-review.md` records which OpenHands V1/Enterprise capabilities to adopt and which to skip; `standalone-operation.md` is the decision record for running with NO OpenHands — it is an optional trigger path, and an outage is `degraded`, never fatal). `docs/ui-guide.md` documents the dashboard VIEW BY VIEW (what each answers, what it refuses to tell you) — pinned by test_event_log.py against the real `data-view` set, so a new view with no entry breaks the build. `docs/observability-epic.md` is the transaction-log/alerting epic (§5.17, diagram 19): `engine/lib/event_log.py` is an append-only JSONL log under `reports/events/` — best-effort (never breaks a caller, degradation reported ONCE and counted), secrets redacted by key-denylist PLUS a length ceiling, `KINDS` closed BY TEST not at runtime. `engine/lib/alert_rules.py` evaluates rules on `make maintain`: firing is a STATE (resolves when clear), cooldown gates the MESSAGE, and an unreadable log reports `unevaluable` NAMING what was lost — never 'ok'. Delivery goes through the Notify port, retries twice, records `notify.sent`/`notify.failed`; test-fire deliberately does NOT retry. Per-rule recipients set `SMTP_TO` (the var `email_notify` actually reads — pinned against the library). `make test-observability` is 9 attacks in `make review`. The SQLite query index is DEFERRED with a written trigger (~300ms query, or retention >90d). `docs/deployment.md` covers the container image, local Compose and OpenShift/Kubernetes manifests under `deploy/`; `docs/review-readonly-rootfs.md` is the R12 writable-path audit — `/app` is code AND state, so mutable paths are RELOCATED via `engine/lib/app_paths.py` (`per-path knob > AIQE_STATE_DIR > ROOT`, defaults byte-identical) rather than volume-mounted over: every mutable dir except `testplans/`+`testdata/` mixes data with code/config, so a mount hides the code and a seeded mount FREEZES it at first boot. `readOnlyRootFilesystem: true` IS SET on both containers in `deploy/openshift/deployment.yaml` and proven against a real `podman run --read-only`; this file claimed the opposite ("still OFF — do not set it") for as long as it had been on, which is the dangerous direction to be stale in: it invites someone to "fix" the manifest by turning the hardening off. First boot into an empty state volume is `bin/container-entrypoint.sh` — see `make test-entrypoint`, which found that it seeded nothing while reporting success.

## Architecture (big picture)

**One pipeline, two modes.** `engine/pipeline.sh {pr|jira}` is the single entry all triggers (`triggers/`) call. Flow: resolve → clone workspace → LLM phase chain → per-repo gate → notify/telemetry.

- **Resolve** (`engine/phases/resolve.py`): deterministic, rules-first routing from `registry/repo-registry.yaml` (testable paths, contract fan-out to consumers, JIRA component/label maps). Below the confidence threshold in `registry/org-config.yaml` it emits `needs_clarification` and the pipeline asks a human instead of guessing. Golden tests in `registry/tests/` pin this behavior.
- **Plan-first mode (human approval gate)**: `pipeline.sh plan <KEY>` stops after the testplan phase (snapshots the contract to `reports/plans/<KEY>.contract.json`, marks the plan `draft`, comments on the ticket) and `pipeline.sh tests <KEY>` resumes into testdata → generate → validate → gate, refusing unless `plan_state.require_approved` passes. The reviewed `testplans/<KEY>.md` is passed to both resume phases so reviewer edits shape generation. `plan` mode writes no run record (it never reaches the gate) so commit-rate metrics stay honest.
- **Multi-agent phases**: two places run more than one agent on purpose. (1) **Generation fans out per test repo** (`GENERATE` in `pipeline.sh` + `engine/lib/merge_contracts.py`): when a run resolves ≥2 test repos, each gets its OWN generate agent, its own `out/repo-conventions-<repo>.md` and a `{{TARGET_REPO}}` instruction confining its writes — so a contract change fanning out to an API repo plus consumer UI repos can't cross-wire their approaches. The labeled per-repo contracts merge back into the single `out/generate.contract.json` shape (each test stamped with `repo`); one repo resolved takes the old single-call path; a per-repo failure is contained (recorded in `fanout.skipped`, other repos still gate) but ALL failing is still a failure. `AIQE_GENERATE_FANOUT=0` disables. (2) **Adversarial test-plan review** (`engine/lib/plan_adversary.py`, `prompts/jira-plan-{adversary,arbitrate}.md`): after `testplan`, a READ-ONLY adversary hunts for what the author missed (negative/boundary/authz/state/cross-repo/data) and an arbiter judges each finding and folds accepted ones in — it may only ADD scenarios, both phases are non-fatal (a failure leaves the authored plan standing), and it runs BEFORE the human approval gate so it changes what the reviewer approves, never whether they are asked. The summary line is stored on the plan state so the ticket comment, Test plans view and wizard all show it. `AIQE_PLAN_ADVERSARY=0` skips. Keep the adversary's `allowed_tools: "Read"` — an opponent that can edit the plan is just a second author.
- **Phase chain**: A = triage → generate → validate (context includes the real PR diff via the Scm `diff` verb; outcome posted as an `ai-qe` build status on the PR head via `set_status`); B = analyze → testplan → testdata → generate → validate (context includes `out/issue-guidance.md` selected from `prompts/issue-types/{story,bug,security}.md` by issue type/labels; `AIQE_INLINE_FILE` bypasses the tracker for pasted-text runs — built by `engine/lib/inline_ticket.py`, `bin/qa.py run-inline`). Every generate AND validate call also receives `out/repo-conventions.md` (`engine/lib/spec_exemplars.py` — deterministic): REAL shared-helper + exemplar-spec code from each resolved test repo, so generated tests follow the repo's EXISTING approach and never introduce a new one (legacy/-path specs are penalized as exemplars; the critic flags `new-approach` deviations; pinned by `registry/tests/test_spec_exemplars.py`). `spec_exemplars.py all <out> <repo...>` writes the combined file AND one per repo in a SINGLE process, profiling each repo once — the fan-out then reuses those files instead of rebuilding (it rebuilds only if one is genuinely missing, so a caller that skipped context prep is never handed an empty approach). Previously 1 + N invocations each re-scanned repos the previous call had read: measured 4.16s across three processes on a two-repo run, component 3306ms -> 1396ms, whole run ~2s faster (interleaved A/B, 4 pairs: +3.8s/+2.9s/-0.2s/+1.9s — one pair inside the noise). Output is byte-identical to the old per-file calls and pinned that way, because this file is context injected into every authoring phase. Each phase is a prompt in `prompts/` run by `engine/phases/run_phase.sh` with per-phase `--allowedTools`/`--max-turns` from `org-config.yaml`, and must emit JSON matching `engine/phases/contracts/*.schema.json`. After `validate`, an **advisory critic** phase (`prompts/critic.md`) scores the generated specs 0.0-1.0 for the defects execution cannot reveal — vacuous/weak assertions, duplicates, brittleness. It is advisory by construction: read-only tools (no Write/Edit), run non-fatally, never read by the gate, and unable to move a review status; `overall` still comes from gate results alone. It feeds the scorecard's *escaped noise* metric (architecture §5.8.7). With `AIQE_MOCK=1`, `engine/phases/mock_phase.sh` stubs every phase so pipeline mechanics run without API spend — the demo targets all use this.
- **Workspace**: sources cloned read-only to `workspace/src/`, test repos read-write to `workspace/tests/<repo>` on branch `test/<KEY>-ai-qe`.
- **Gate** (`engine/gate/gate.sh`): deterministic, runs *inside* each test repo, and is the ONLY place `git push` (or commit) happens. Ordered checks with distinct exit codes: scope + unsafe-filename charset (2), born-mapped catalog sidecar (4), lint, execute changed specs inside the provisioned env (5), secret scan (3), refuse-if-not-a-standalone-repo (6), push-failed-with-remote (7 — only the no-remote demo case is skippable). Emits machine-readable `GATE_STATUS=COMMITTED|NO_CHANGES`. `AIQE_GATE_CHECK_ONLY=1` runs every check but stops before commit/push (`GATE_STATUS=WOULD_COMMIT`) — used by the OpenHands Stop hook (`.openhands/hooks.json` → `.openhands/hooks/gate-check.sh`) so an agent is blocked from declaring a task done when the gate would reject it; the hook never writes and fails open. Framework-agnostic: lint/test commands come from each test repo's `.ai-qe/config.yaml`.
- **Environment (G5)**: `bin/with-env.sh` reads `test_env` from the test repo's `.ai-qe/config.yaml` — `compose` mode boots the app-under-test (resolved `workspace/src/` first, then `demo/`) on a random port with guaranteed teardown via trap; `shared` mode just exports the URL env var.
- **Ports & adapters**: the pipeline only calls `SCM`/`TRACKER`/`NOTIFY`/`TELEM`/`PHASE` shell functions. Real adapters live in `adapters/{scm,tracker,knowledge,cicd,notify,telemetry}/`, mocks in `adapters/mock/`; both speak the same verbs (conformance-tested; unknown verb exits 64). The engine never imports a vendor. The Notify port has two channels — Slack (`adapters/notify/slack.sh`) and Email/SMTP (`adapters/notify/email.sh`, backed by `engine/lib/email_notify.py`); `NOTIFY_KIND=slack|email|both` (default slack) selects them. Email also powers on-demand run-summary / review-digest / team-report emails (`bin/qa.py email …`, `make email`, dashboard `/api/email/*`); with no `SMTP_HOST` it writes `out/mock-email/*.eml` so it's demoable.
- **Catalog** (`catalog/`): every test maps to app repos with evidence + confidence. The per-run existing-test context (`out/catalog-slice.jsonl`, `engine/lib/catalog_slice.py`) is FILTERED by the same `covers:` mapping that routed the run — it used to be a concatenation of every `catalog/*.jsonl`, so a PR resolving one API repo also received the UI repo's rows (token cost + dilution on a real estate, and a contradiction of the fan-out design). Relevance = rows from a resolved test repo, plus rows from ANY repo covering a source repo this run touched. The generate fan-out swaps in a PER-REPO slice exactly as it swaps per-repo conventions. An empty selection FALLS BACK to the whole catalog and says so: starving generation of existing-test context makes it duplicate work it cannot see, which is worse than over-feeding it. Bootstrap pipeline: extract (regex AST proxy) → correlate (endpoint↔OpenAPI contract, route↔route table, JIRA keys from git log) → LLM-classify residue → tier into auto (≥0.85) / review queue / orphan. `covers:` in the registry is regenerated from the catalog by `regen_coverage.py` — never hand-edit it. `engine/lib/coverage_gaps.py` diffs harvested surface against catalog evidence (pipeline context `out/coverage-gaps.md`; AGENTS.md marks uncovered surface `[NO TEST]`); `engine/lib/test_health.py` ingests CI results into `catalog/health.json`; `catalog/bootstrap/index_db.py` mirrors it all into the gitignored SQLite index.
- **Estate knowledge (`AGENTS.md`)**: auto-generated by `bin/gen_agents_md.py` from registry + catalog + harvested contracts/route tables + per-repo guidance; injected as context into every LLM phase and regenerated by pipeline runs, onboarding, bootstrap, `bin/repos.py`, and `bin/qa.py` mapping edits. Never hand-edit it. Repo configuration changes go through `bin/repos.py` / `engine/lib/repo_admin.py` (validates, re-runs goldens, regenerates AGENTS.md; skips the pytest re-run when already inside pytest — keep that guard). Test repos carry a hand-managed `scope` (declared app-repo responsibility, edited via `repos.py scope` or the dashboard Repositories view); `covers:` stays generated as catalog evidence ∪ scope (`regen_coverage.py`). Per-repo guidance = team notes in `knowledge/repos/<name>.md` + any `AGENTS.md`/`CLAUDE.md` belonging to the repo itself — both merged into AGENTS.md's "Repository guidance" section and thus into every authoring phase (PR triage/generate, JIRA analyze/testplan/testdata/generate). Repo-local files come from the workspace clone, the `knowledge/synced/<repo>/` cache, the **curated** copy under `knowledge/curated/<repo>/` (TRACKED, user-edited via the Repositories view — `engine/lib/curated_guidance.py`), or `demo/` — clone vs cache is decided by **freshness** (a just-synced file beats a leftover clone; a fresh clone beats an older sync), so a manual sync is never a silent no-op; ranking after that is curated > demo fixture > generated, so curating never overrides a repo-owned file. Repos that ship no guidance at all get a **generated** `AGENTS.md` under `knowledge/generated/<repo>/` (gitignored scratch — `bin/gen_agents_md.py` rebuilds whatever is missing before it runs, so a fresh clone self-heals), ranked BELOW every real source so a committed file always wins — this is what makes a newly-added repo (app or E2E) still teach the phases its surface, layout and scope. `engine/lib/guidance_sync.py` pulls them from the SCM without cloning via the Scm port's `fetch_file` verb (exit 3 = absent) for app repos (ui + service) *and* E2E test repos: `make sync-guidance [REPO=..] [REF=..]`, `make sync-status`, `bin/repos.py sync|sync-status`, dashboard `GET/POST /api/repos/sync` + the Repositories view's Sync buttons.
- **QA operations** (`bin/qa.py`, `bin/dashboard.py`): every pipeline run persists a structured record to `reports/runs/<RUN_ID>.json` (per-phase contracts + per-repo gate status/exit/commit; assembled by `engine/lib/run_record.py` from `out/gate_results.tsv`) and archives each gate commit as `reports/runs/<RUN_ID>-<repo>.diff` (workspace is ephemeral — the diff is the durable copy of generated test code; `bin/qa.py artifacts <KEY>` is the viewer). Team-review state per PR/JIRA key lives in `reports/runs/reviews.json` via `engine/lib/review_state.py` (statuses: pending_review/in_review/approved/changes_requested; a committing run auto-resets its key to pending_review). The same store tracks each key's target `release`: auto-captured from the ticket's `fix_versions` in the jira pipeline branch, `bin/qa.py release <KEY> <version>` for PRs. The manual work queue (`engine/lib/work_queue.py`, `reports/runs/queue.json`) feeds `pipeline.sh` from the served dashboard (`bin/dashboard_server.py`) or CLI; Python subprocesses must launch bash via `work_queue.bash_exe()` — plain `"bash"` resolves to WSL's System32 stub outside Git Bash. State-file mutations go through `engine/lib/fs_lock.py` (mkdir-based advisory lock — keep new mutations inside it; a pin now FAILS THE BUILD on an unlocked read-modify-write in plan_state/review_state/work_queue/openhands_events). `read_json_guarded` quarantines a CORRUPT file and — since the pass-C review — RAISES on an unreadable one after a short retry: the file exists, so reporting it as empty made the caller's next save destroy it (verified: one transient OSError turned an approved plan into {}). `state_bundle` import containment is a PATH test (`root in target.parents`), never a string prefix — `startswith` accepted a sibling `<root>-evil/` directory. See docs/review-gate-and-core.md. Budgets are enforced: `engine/lib/budget.py` meters each real phase's reported spend into `out/cost.tsv` and the pipeline checks cost + wall-clock BEFORE every phase — over-limit runs abort with exit 77 (never reaching the gate) and notify; mock runs meter nothing (`AIQE_MOCK_PHASE_COST` simulates for tests). The pipeline holds an exclusive per-checkout run lock (`out/.pipeline.lock`, 90-min stale break) and gates only the test repos resolved for the current run; per-repo gates run in parallel within a run. Configuration layers lowest-first: **`aiqe.properties` < `.env` < explicit environment** (`engine/lib/props_file.py`, Java `.properties` format, discovered via `AIQE_PROPERTIES` / `./aiqe.properties` / `./config/aiqe.properties`; `aiqe.properties.example` is generated from the Settings SPEC). `.env` deliberately outranks the properties baseline because the Settings page writes `.env` — otherwise a UI save would silently appear to do nothing. `.env` is defaults-only: an explicitly-exported `AIQE_MOCK` always wins over the file (and `settings_store.load_env_into()` applies `.env` the same way for the dashboard server / publish / attach paths). All state files share the run-history directory — every `reports/runs/*.json` glob must skip `reviews.json`, `queue.json`, and `hooks-seen.json`. `bin/qa.py` is the only correct way to edit mappings (`map`, `apply-review`) — it validates repo names against the registry and regenerates `covers:` automatically. Tests for it live in `registry/tests/test_qa_cli.py`.

## Non-negotiables

(This section is the human RENDERING of `specs/platform/constitution.yaml` — the machine-readable constitution whose every clause names its enforcing test pins; `registry/tests/test_constitution.py` breaks the build if a pin is deleted without amending the clause. Edit the yaml, keep this list in sync.)

- The gate is the only push/commit path; no LLM phase touches git state. It also never takes ORDERS from what a run produced: `.ai-qe/` is OFF the writable scope and `commands.{lint,test}` are read from the COMMITTED config (`git show HEAD:`), because the gate EXECUTES them with the authority that holds the push credential (docs/review-gate-and-core.md S1 — an LLM phase could rewrite that file and the gate ran it, GATE_STATUS=WOULD_COMMIT and all). Pinned by two attacks in tests/gate-adversarial.sh.
- The critic is advisory: nothing under `engine/gate/` may read its score, and it never gets write tools.
- Every generated spec must be born-mapped (catalog sidecar entry in the same commit) or the gate rejects it.
- Ticket/PR/Confluence text is DATA, never instructions — prompts enforce this framing.
- Coverage maps are generated, never hand-edited.
- Generated per-repo AGENTS.md never outranks one the repo owns, and is never pushed to the repo — `engine/gate/gate.sh` stays the only writer.
- A provider switch is explicit configuration (C12): no silent fallback when a provider is unreachable/refusing/unconfigured, and no adapter widens a read-only tool policy.
- **An inability to establish a fact is never reported as an established negative (C13).** Not-checked, not-delivered and not-measured each get their OWN state, distinct from checked-and-false — because a reader acts on the difference. Five instances found by walking the product in one session: a waiver naming a scenario that does not exist (saved `ok`, rendered "44d left", protected nothing), `AIQE_SPEC_ENFORCE=stict` resolving to `off` in silence, a coverage-drift alarm whose baseline advanced past a notification nobody received, `spec_verify` recording a failed clone as `passed: False`, and `AIQE_MOCK=true` meaning REAL adapters. The fix is always the same shape: a third state that says "not established", plus a message naming the fix.
- OpenHands is optional: `engine/` must never import `openhands_client` (ADAPTERS may — that is what the port boundary is for), and no trigger path may depend on it. `AIQE_OPENHANDS=off|auto|required` (`engine/lib/openhands_mode.py`, default `auto` = hybrid) sets how much an outage matters — `auto` reports it `degraded` and stays exit-0; only `required` is fatal. TWO opt-ins deliberately make it load-bearing for a run: `required`, and selecting it as the LLM provider (`AIQE_OPENHANDS_PROVIDER=1`), which is load-bearing by construction because there is no silent fallback. `registry/tests/test_standalone.py` + the slice-5 pins in `test_llm_runner.py` pin all of it.

## Demo estate gotchas

- `demo/` repos are plain directories — nested `.git` dirs can't be committed to this scaffold. Anything that treats a demo copy as a git repo MUST initialize it first: `adapters/mock/scm.sh` `ensure_git` does this on clone, and `bin/demo-bootstrap.sh` rebuilds JIRA-keyed history from each spec's header comment (that's what feeds the correlator's `git_history` evidence). A copy without `.git` makes git commands silently escape to this scaffold's own repo — the gate's exit-6 check is the backstop; never bypass it.
- Demo repos each carry `package.json` with `"type": "commonjs"` so a stray `package.json` in an ancestor directory can't flip Node's module mode.
- This repo is developed on Windows under Git Bash: keep scripts POSIX-sh compatible, build Python paths with `pathlib` (never split `__file__` on `/`), pass `stdin=subprocess.DEVNULL` to subprocesses in tests, and avoid non-cp1252 characters in `print()` unless stdout is reconfigured to UTF-8.
- `workspace/`, `out/`, `knowledge/generated/`, and `.env` are gitignored scratch; `reports/*.log` are run artifacts.

## Real-estate rollout deltas

`AIQE_MOCK=0` switches to real `claude -p` phases and real adapters (credentials via `.env`, see `.env.example`). Real test repos set `commands.test: npx playwright test` in `.ai-qe/config.yaml`; the demo uses `node --test` — the gate doesn't care. Onboard a new source or test repo with `bin/onboard.sh` (idempotent; writes the registry entry, drops templates, triggers bootstrap), then re-run `make test-routing`.
