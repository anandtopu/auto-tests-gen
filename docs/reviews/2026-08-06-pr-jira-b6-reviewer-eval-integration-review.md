# B6 Reviewer Evaluation — Cross-file Integration Review

Date: 2026-08-06
Scope: correctness, security, reliability, deployment, and coverage
Result: Ready to commit; real-model quality remains explicitly unmeasured

## Correctness

- The evaluator's category universe is imported from the production reviewer,
  preventing an evaluation-only category list from drifting.
- Fixture and label IDs must match exactly. Each production class occurs once,
  one clean control occurs once, and the fixed 100% M3 threshold cannot be
  lowered by editing labels.
- Catch credit requires verdict, exact category set, grounded file/test, and
  labelled evidence terms. Clean credit requires approve with zero findings.
- A measured real failure now fails the combined artifact. The first version
  returned a failing command but retained a passing artifact headline; this was
  fixed and regression-tested.

## Security and trust boundaries

- Fixture references are confined to sibling file names and fixture bytes are
  SHA-pinned to the QE-owned labels. Embedded source is framed as untrusted DATA.
- The evaluator reuses the bounded production reviewer normalizer rather than
  accepting free-form model output. Mock-marked output is never eligible for a
  real-model measurement.
- The real target uses the configured provider/model and the reviewer phase's
  read-only tool policy. It does not edit application or test repositories.

## Reliability and cost

- Default `make reviewer-eval`, `make eval`, and `make review` execute only
  deterministic scripted contracts. They do not call a provider.
- `make reviewer-eval-real` is explicit and potentially billable, checks the
  configured adapter, uses bounded per-fixture timeouts, validates every output
  through the reviewer schema/normalizer, and returns nonzero on unavailable
  auth or a missed attack.
- Scorecard and CLI surfaces render simulated and real evidence independently.
  The integration pass fixed the initial omission of real catch rate and clean
  outcome from those renderers.

## Deployment and compatibility

- No dependency, image, manifest, migration, state-store, feature-flag default,
  gate, human-review transition, or delivery-policy change is introduced.
- The result remains in the existing ignored `eval/results/` workspace and is
  regenerated by normal evaluation commands.
- Focused B6 tests: 16 passed. Related compatibility tests: 76 passed. Full
  registry suite before the final read-only-policy pin: 1,511 passed in 718.52
  seconds; the final focused/related suites cover that hardening. Python compilation and direct
  evaluator/scorecard smoke checks passed.
